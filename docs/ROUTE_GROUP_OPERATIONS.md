# Route group rollout (option 1)

The Admin Route Groups page now controls a dedicated WireGuard transport from each Iran entry to one Turkey gateway. Each group reserves a private /24 link network, a UDP port on Turkey, and a unique Linux policy table. Entries use link addresses `.2` onward; Turkey uses `.1`. The entry's client CIDR is sent through its group link when active. Turkey routes replies back through that peer and masquerades client traffic on its configured egress interface. Every member runs its own enrolled agent with access only to its own private route key.

1. Configure distinct client `tunnel_cidr` ranges for all entries and a nonoverlapping private /24 for the group. Give the Turkey host's agent a public endpoint, ensure UDP `link_port` reaches Turkey, enable IPv4 forwarding on the hosts, and allow Docker's `DOCKER-USER` chain. The agent requires the existing WireGuard, iproute2, and nftables binaries. Its Compose container already has host networking and NET_ADMIN.
2. Create a group in Admin and wait for each member's signed desired-state poll to publish a route public key. `Check health` must show inventory and key exchange ready.
3. Press `Stage`. Agents install dedicated `hcr*` interfaces and keys only. The Iran agent initiates a WireGuard session and probes a UDP echo at the Turkey link address. No client policy route or egress NAT is installed yet.
4. Once all members report fresh health, press `Activate`. The agents add only the owned policy route, return routes, forwarding rules, and Turkey NAT. Users already connected to an Iran entry then use Turkey egress on the next reconcile cycle. Each active agent checks the encrypted link at every poll.
5. `Disable` stops new desired instructions; the agents withdraw their owned routes, NAT, forwarding rules, and dedicated interface on the next poll. On an unhealthy report, stale heartbeat, stale active report, or staging timeout, the backend marks the group failed and stops issuing it. Agents withdraw routes on control-plane loss after 45 seconds. Use `Disable`, repair the issue and stage again.

The group transport uses direct Iran-to-Turkey hops. The separate Iran1→Iran2→Turkey relay selection and Windows multi-entry switching remain separate work. The Admin panel orchestrates enrolled agents; it cannot install agents or open cloud firewall ports by itself. This code and the isolated network namespace test do not replace field validation on your actual servers. Do not run the standalone lab script on a production host: it creates temporary network namespaces and firewall tables.
